The frame

Every SOP answers one of three questions

01 / Context

Context.

AI is only as good as what you feed it. Context is finite — manage it like RAM.

02 / Verify

Verification.

If you can't verify it, don't ship it. Tests, builds, screenshots — evidence, not promises.

03 / Ownership

Ownership.

You own every committed line, including the ones AI wrote. AI holds the pen, not the decision.

Foundations

Why AI gets it wrong

Understand how an LLM works and every later SOP has a reason — instead of being dogma.

Say

Phần khoa học ngắn để mọi SOP sau có gốc. Đừng sa đà học thuật — ba ý là đủ.

The model

Hallucination is a property, not a bug

  • Next-token prediction. It optimizes for plausible, not correct. No internal truth-check.
  • The context window is finite — and rots as it fills. The model forgets early instructions and makes more mistakes.
  • Consequence. Feed it a 10,000-line file → it forgets the start and fabricates. Fix: break the problem down before you prompt.
Say

AI-Assisted Workflow

Prompt → Context → Iterate → Workflow for big tasks. The heart of the talk.

Say

Writing effective prompts

More specific = fewer corrections

✗ Vagueadd tests for foo.py
✓ Context + criteriawrite a test for foo.py covering the edge case where the user is logged out. avoid mocks.

Show examples, not descriptions · long docs first · include success criteria · name the technique (few-shot, chain-of-thought).

Say

Prompt tồi không phải vì viết dở tiếng Anh — mà vì bạn giấu context mà chỉ bạn biết.

Nguồn: Anthropic Claude Code Best Practices; promptingguide.ai.

Example · Postgres

Don't ask "write me the SQL"

Bad prompt

"Write SQL to get orders by user."

→ nothing for it to optimize.

Good prompt

Schema + existing indexes + row counts + EXPLAIN ANALYZE of the current query + the goal.

It sees what the DB sees.

A bad prompt hides the context only you have.

Say

Đây cũng là đáp án checkpoint Medium. Kiểm chứng với planner, không với model: chạy EXPLAIN thật sau khi AI đề xuất.

Nguồn: PostgreSQL docs — Using EXPLAIN.

Context management

A long chat is not a badge of honor

4 techniques

Compaction (summarize history) · note-taking (external memory: todo.md) · sub-agents (delegate file reading, get summaries back) · just-in-time retrieval.

In practice

/clear between unrelated tasks. Corrected the AI twice on the same thing and still wrong? Context is dirty — clear and rewrite a better prompt.

Clean context + a good prompt almost always beats a long dragging chat.

Say

Lịch sử hội thoại là đòn bẩy mạnh nhất và cũng dễ làm hỏng nhất. File CLAUDE.md / quy ước dự án: giữ ngắn, mỗi dòng tự hỏi "bỏ dòng này thì AI có sai không?".

Big task? Make the AI interview you first

Explore

Step 2

Step 3

Code

Small steps, a test each.

Commit

Checkpoint often.

Performance & testing

Two places AI is "green but wrong"

Performance

The four smells: N+1 queries · missing index · unbounded findAll() · accidental O(n²).

All pass every unit test. All fine on ten rows.

Bad tests

High coverage ≠ safe. Mock overuse · asserting current behavior instead of correct → a green test just freezes the bug.

SOP — a human writes at least one edge-case test the AI missed, and always runs it to see it actually pass.

Say

Performance không có bài đọc — dùng ví dụ thật từ codebase. Test dởm: xoá business rule mà test vẫn pass → đó không phải test.

Nguồn: HackerNoon Limits of LLM-Generated Unit Tests; arXiv empirical study về unit test generation.

Section 7.3

Documentation

Give AI the pen — not the decision.

Say

Ngắn, một slide. Ranh giới "AI cầm bút, người quyết" rõ nhất ở docs và ADR.

Docs · API · ADR

AI drafts; a human reviews and decides

Docs from code

Generate docs from real code (safe). Warning: AI docs "sound right but are technically wrong" exactly where it's complex — where docs matter most.

API · Diátaxis

Four types for four needs: tutorial · how-to · reference · explanation. AI writes any fast; which type for whom is your call.

ADR

Title / Status / Context / Decision / Consequences. An ADR is a decision with its expiry conditions. AI may draft it, never decide it — it fabricates rationale the team never discussed.

Say

Cho AI cầm bút, đừng cho AI cầm quyền quyết. Docs và ADR là nơi ranh giới đó rõ nhất. ADR bất biến; quyết định mới thì viết ADR mới supersede cái cũ.

SOPs for common tasks

One SOP frame, filled per task.

Say

Phần này phụ thuộc stack của team — trình bày dạng khung SOP rồi mời khán giả điền.

Khung 4 bước: nạp context chuẩn (template, PR mẫu, convention, schema) → cho AI cách tự kiểm (test/build/lint) → verify rủi ro đặc thù của loại task → người ký tên trước khi merge.

Migration checklist (Fowler): nhỏ / tăng dần · versioned cùng code · có rollback · chạy tự động giống nhau mọi môi trường · breaking change dùng parallel change. Endpoint: validate input, auth, error handling. Integration test: chạm biên thật (DB thật / container), không mock hết.

Checkpoint questions

Easy

Copy-pasting straight from an LLM into prod — what's the danger?

Medium

How do you structure a prompt for a Postgres-optimized SQL query?

Hard

AI generated an email regex. It looks correct. Your SOP to verify it's safe against ReDoS?

ReDoS — a bad regex → catastrophic backtracking → one crafted request pins a CPU. "Looks right" ≠ "safe".

Answers (don't print)

Easy. Không phải "nó có thể sai" (mọi code đều vậy). Nguy hiểm cụ thể: nó hợp lý, nên sống sót qua lần đọc lướt vốn chỉ bắt code sai rõ ràng — và sau này không ai có mental model để debug. Thêm: lỗ hổng OWASP (secret hardcode, SQLi), rò rỉ dữ liệu (vụ Samsung), và bạn vẫn là người chịu trách nhiệm.

Medium. Đưa DDL, index hiện có, số dòng, version Postgres, và EXPLAIN ANALYZE hiện tại. Yêu cầu nó nói plan nó kỳ vọng. Rồi chạy EXPLAIN thật. Kiểm chứng với planner, không phải với model.

Hard. Đọc regex tìm nested quantifiers (a+)+ và overlapping alternation (.|\s)* — hình dạng gây catastrophic backtracking. Test bằng input đối nghịch (prefix mơ hồ dài + một ký tự làm fail, vd "a"×40 + "!"), đo thời gian — không được tăng siêu tuyến tính. Dùng engine tuyến tính (RE2) · đặt timeout · giới hạn độ dài input. Rồi chất vấn tiền đề: validate email bằng regex là sai công cụ — check @, cap length, gửi mail xác nhận. Một request khéo là đủ treo CPU. "Trông đúng" ≠ "an toàn".

Why the discipline survives

Full autonomy doesn't remove humans — it changes their shape

Earned trust

You don't hand over production on day one: read-only → write-to-branch → staging → production, expanding access by proven reliability. Limit each agent's blast radius.

DeepSeek Harness

Open-source agent harness, "everything is a plugin" (even the agent loop). Append-only, inspectable session log: every prompt, tool call, context, token — auditable even when the agent runs itself.

Today's SOP = the manual version of the same discipline. This is your Verification + Ownership pillars, encoded into guardrails + audit trails. Discipline scales — it doesn't vanish.
